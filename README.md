# AI-Doc-Assistant

A beginner-friendly document management REST API built with **FastAPI**. This project implements basic health checks, document uploads, and document listing using in-memory storage.

## Features

- **Health Check:** Verify that the API is running.
- **Upload Documents:** Upload PDF, TXT, and DOCX files.
- **File Validation:** Reject unsupported file types, empty files, and files larger than 10 MB.
- **List Documents:** Retrieve metadata for all uploaded documents.
- **API Documentation:** Explore and test endpoints through Swagger UI.
- **Automated Testing:** Test API functionality using Pytest and FastAPI TestClient.

## Tech Stack

- Python 3.12+
- FastAPI
- Uvicorn
- Pydantic
- Pytest
- HTTPX

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/HarshAgarwal4/AI-Doc-Assistant.git
cd AI-Doc-Assistant
```

If you have already cloned the repository, open its root directory in your terminal.

### 2. Install dependencies

```bash
uv sync
```

This installs the dependencies declared in `pyproject.toml` and creates or updates the project's virtual environment.

### 3. Run the application

```bash
uv run uvicorn app.main:app --reload
```

The API will be available at:

- **Base URL:** http://127.0.0.1:8000
- **Swagger UI:** http://127.0.0.1:8000/docs
- **ReDoc:** http://127.0.0.1:8000/redoc

## API Endpoints

### 1. Health Check

**Endpoint:** `GET /health`

Checks whether the API is running.

Example response:

```json
{
  "status": "ok"
}
```

Expected status code: `200 OK`

### 2. Upload a Document

**Endpoint:** `POST /documents`

Uploads a document and returns its metadata.

**Supported file formats:**

- PDF (`.pdf`)
- Text (`.txt`)
- Word document (`.docx`)

**File size limit:** 10 MB.

**Example success response:**

```json
{
  "id": "generated-document-id",
  "filename": "example.pdf",
  "content_type": "application/pdf",
  "size_bytes": 1024,
  "uploaded_at": "2026-10-28T10:00:00Z"
}
```

The ID and upload timestamp are generated by the application. The example values are illustrative.

**Possible status codes:**

| Status code | Description |
|---|---|
| `201 Created` | Document uploaded successfully |
| `400 Bad Request` | File is empty or required filename information is missing |
| `413 Content Too Large` | File exceeds the 10 MB limit |
| `415 Unsupported Media Type` | Unsupported file extension |
| `422 Unprocessable Entity` | Required request data is missing or invalid |

### 3. List Uploaded Documents

**Endpoint:** `GET /documents`

Returns metadata for all documents uploaded during the current application run.

Example response:

```json
[
  {
    "id": "generated-document-id",
    "filename": "example.pdf",
    "content_type": "application/pdf",
    "size_bytes": 1024,
    "uploaded_at": "2026-10-28T10:00:00Z"
  }
]
```

If no documents have been uploaded, the API returns an empty list:

```json
[]
```

Expected status code: `200 OK`

## Testing

Run the test suite using:

```bash
uv run python -m pytest -v
```

To run a specific test file:

```bash
uv run python -m pytest tests/test_documents.py -v
```

The tests should cover the health endpoint, successful document uploads, document listing, empty-file validation, unsupported file formats, and file-size limits.

## Storage Limitations

This project uses an **in-memory Python list** to store document metadata.

- Uploaded document metadata is available only while the application process retains it.
- Metadata is lost when the application restarts.
- Uploaded file contents are validated but are not permanently stored by this implementation.
- No database or persistent file storage is configured.

Database integration and persistent storage can be added in future assignments.
